# Разработка и проверки

Для обычного знакомства с проектом достаточно Docker и команды из [README](../README.md). Этот документ нужен для изменения кода и запуска тестов.

## Запуск без Docker

Требования: Node.js 22.23.4 (см. `.nvmrc`), npm 11.21.1 и запущенная PostgreSQL 17.

1. Установите зависимости: `npm ci`.
2. Скопируйте `.env.example` в `.env`: `cp .env.example .env`. В PowerShell: `Copy-Item .env.example .env`.
3. Создайте локальную БД `credit` и укажите её адрес, пользователя и пароль в `DATABASE_URL` файла `.env`.
4. Подготовьте базу и запустите приложение:

```sh
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте http://localhost:3000. Если PostgreSQL запущена в Compose, её порт по умолчанию не опубликован на хосте. Для разработки без Docker используйте отдельный доступный экземпляр БД.

## Переменные окружения

Начальные значения для разработки находятся в [`.env.example`](../.env.example). Настройки production описаны в [инструкции деплоя](../deploy/GITHUB_SECRETS.md).

| Переменная                 | Назначение                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `DATABASE_URL`             | Адрес PostgreSQL для приложения и миграций.                                                                              |
| `POSTGRES_PASSWORD`        | Пароль БД в Compose. Публичное значение по умолчанию подходит для локального демо; на VPS используется случайный пароль. |
| `APP_ORIGIN`               | Адрес приложения для проверки запросов, локально `http://localhost:3000`.                                                |
| `COOKIE_SECURE`            | `false` для локального HTTP, `true` для HTTPS.                                                                           |
| `DEMO_MODE`                | `true` включает демоаккаунты при seed и готовые финансовые показатели.                                                   |
| `UPLOAD_DIR`               | Приватная папка PDF; локально `./work/uploads`, в Docker `/data/uploads`.                                                |
| `APP_PORT`, `BIND_ADDRESS` | Порт и адрес приложения в Compose; по умолчанию `3000` и `127.0.0.1`.                                                    |
| `TEST_DATABASE_URL`        | Отдельная тестовая БД с именем, оканчивающимся на `_test`.                                                               |
| `BASE_URL`                 | Адрес приложения для E2E и проверки сохранения данных.                                                                   |
| `IMAGE_BASE`, `IMAGE_TAG`  | Образы и версия для деплоя из GHCR.                                                                                      |
| `NEXT_TELEMETRY_DISABLED`  | Значение `1` отключает телеметрию Next.js.                                                                               |

## Проверки

После `npm ci` и `npm run db:generate`:

| Команда                    | Что проверяет                                                                                                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`            | TypeScript, unit/UI-тесты с покрытием, API-контракты и OpenAPI.                                                               |
| `npm run test:deploy`      | Ветви скрипта деплоя с заглушками, без доступа к серверу. На Windows нужен Git Bash; другой путь можно указать в `BASH_PATH`. |
| `npm run build`            | Production-сборку.                                                                                                            |
| `npm run test:integration` | API и операции с настоящей тестовой PostgreSQL.                                                                               |
| `npm run test:e2e`         | Пользовательские сценарии в Chromium на запущенном приложении.                                                                |

Для integration создайте отдельную БД, например `credit_test`. Установите **обе** переменные `DATABASE_URL` и `TEST_DATABASE_URL` в один и тот же адрес этой БД, выполните `npm run db:migrate`, затем `npm run test:integration`. Тесты очищают данные тестовой базы; рабочую БД использовать нельзя. При отсутствии подходящей БД тесты завершаются ошибкой.

Для E2E сначала запустите приложение с демоаккаунтами и подготовленной БД. Затем выполните `npx playwright install chromium` и `npm run test:e2e`. Отчёт находится в `playwright-report/`. E2E создают заявки, поэтому для них удобно использовать отдельный локальный стенд.

Пороги покрытия кредитного ядра: 90% statements/lines/functions и 80% branches. Фактические результаты записываются в [verification.md](verification.md).

Проверка сохранения заявки и PDF после перезапуска приложения:

```sh
node scripts/persistence-probe.mjs before
docker compose restart app
node scripts/wait-for-ready.mjs
node scripts/persistence-probe.mjs after
```

## API

Swagger UI доступен по `/api-docs`, OpenAPI — по `/api/v1/openapi`. [Коллекция Postman](postman.collection.json) и [локальное окружение](postman.local.environment.json) лежат рядом.

Для запросов, меняющих данные, обязателен заголовок `Origin`. Для отправки заявки и принятия предложения также нужен `Idempotency-Key` в формате UUID. После сетевого сбоя повторяйте тот же ключ и тело запроса, чтобы не создавать повторную операцию.

## Ограничения прототипа

- Один экземпляр приложения и локальное хранилище файлов. Горизонтальное масштабирование не реализовано; ограничитель попыток входа хранится в памяти процесса.
- PDF проверяются по расширению, MIME и сигнатуре. Содержание не распознаётся, антивируса нет; финансовые показатели вводятся вручную.
- В интерфейсе используется обозначение «МБ». Предел одного PDF — 5 × 1024² байт; общий лимит заявки с историей — 25 × 1024² байт.
- Исторические PDF автоматически не удаляются. При аварии между записью файла и транзакцией может остаться файл без записи в БД.
- Внешние реестры и БКИ заменены локальными симуляторами. Их ответы определяются синтетической компанией.
- Деплой сохраняет резервную копию БД. Откат образа приложения не откатывает схему: миграции должны быть обратно совместимыми, восстановление БД выполняется отдельно.
